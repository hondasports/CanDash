# 実車検証計画

状態: 計画のみ（未実施）
最終更新: 2026-10-24

## 1. 目的

[事前調査](research/mazda3-bp-obd-can.md)の推定を、実車で確定させる。

1. OBD-II ポートに CAN のブロードキャストが流れているか
2. 標準 PID（モード 01）に応答するか
3. 独自 PID（UDS `22xxxx`）に応答するか

## 2. 事前準備

- [ ] 無通電で CAN Unit の CAN-H と CAN-L の間の抵抗を測り、終端抵抗の有無を確認する
- [ ] イグニッション OFF で、OBD の 6 番と 14 番の間の抵抗を測る（約 60Ω なら正常に終端されている）
- [ ] イグニッション ON で、6 番と 14 番の電圧を測る（CAN-H は 2.5〜3.5V、CAN-L は 1.5〜2.5V 程度が目安）
- [ ] microSD を FAT32 でフォーマットする
- [ ] 本体の時刻を合わせる

## 3. 検証手順

### 検証 1: ブロードキャストの有無（モード A）

1. 受信専用、500kbps で記録を開始する
2. イグニッション ON、エンジン停止の状態で 30 秒記録する
3. エンジンを始動し、アイドリングで 30 秒記録する
4. 記録を停止し、サマリを確認する
5. フレームが 0 でエラーも 0 の場合は、PIN SWAP を行って 1〜4 を繰り返す

### 検証 2: 標準 PID（モード B）

1. エンジンを始動し、停車した状態にする
2. モード B で 30 秒記録する
3. `7E8`（PCM の応答）などが記録されているかを確認する

### 検証 3: 独自 PID（モード C、任意）

1. 検証 2 で応答を確認できた場合にのみ行う
2. 既知の PID から低頻度で試す

## 4. 結果の判定

### 検証 1

| フレーム数 | エラー | 判定 | 次の行動 |
|---|---|---|---|
| 0 | 0 | バスが静か（診断用 CAN）、または配線の断線 | 電圧の測定結果と検証 2 で切り分ける |
| 0 | 増加している | 何かが流れているが受信できていない | ビットレートの変更、または CAN-H/L の接続を確認する |
| 1 以上 | — | ブロードキャストがある | 事前調査の推定は外れ。ID 別に解析する |

### 検証 2

| 結果 | 判定 |
|---|---|
| `7E8` などの応答がある | 診断要求でデータを取得できる |
| 応答がない | 配線、ビットレート、要求の形式を確認する |

## 5. 結果の記録

検証の結果は `docs/results/` に日付ごとのファイルで残す。

記録する項目:

- 日時、車両の状態（イグニッション、エンジン）
- 使用したファームウェアの版、モード、ビットレート、ピン設定
- サマリの内容（フレーム数、ID 数、エラー）
- 判定と根拠（ログファイル名、該当箇所）
- 事前調査の推定のうち、確定したもの・外れたもの
